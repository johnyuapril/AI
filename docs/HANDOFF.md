## 최근 변경 (2026-11-01 오후)
- 한글(HWP) 불러오기 고침: 본문 섹션을 못 찾던 문제. 파일 확장자 대신 파일 내용으로 형식 판단. 배포용/암호 HWP는 안내 메시지.
- PDF 한글 글꼴(CID) 읽기: pdfjs cMap/표준 글꼴을 빌드 때 public/pdfjs 로 복사(prebuild).
- 표지(첫 씬 앞 제목·날짜)는 지문으로.
- 버전 표시와 업데이트: 홈 화면에 버전, "업데이트 확인" 버튼. 새 버전이 있으면 앱 안에서 APK를 받아 설치 화면을 띄움 (android AppUpdaterPlugin.java, src/update.ts). 저장소가 공개여야 동작(비공개면 다운로드 페이지를 엶).
- 저장소: 사용자가 AI2를 AI로 이름을 바꾸고 공개로 전환함. 이제 johnyuapril/AI 하나만 씀. 앱 업데이트도 AI의 릴리스를 봄.

- 구글 자동 저장: 사용자의 구글 앱스 스크립트 웹 앱(코드: tablet-app/src/google-sync.gs.txt, 앱의 "구글 연결" 창에서 비밀 키가 채워진 채로 복사)에 POST. 드라이브 "시나리오 작업실" 폴더에 대본 문서, 장면 묘사 문서, 신 리스트 스프레드시트(신 리스트/컷 리스트/장면 묘사 탭)를 만들고 덮어씀. 고친 뒤 1분, 작품을 닫거나 앱이 뒤로 갈 때 자동 업로드. 사용자가 연결까지 성공함. 코드 v2: Paragraph.setText 가 void 를 돌려줘서 이어 쓰기(체이닝)하다 깨지던 문제 고침. 코드 v3: 시트를 앱의 신 리스트처럼 (씬 줄 + 접힌 컷 줄 묶음, 열 너비·색), 장면 묘사 탭도 같은 모양, 컷 리스트 탭은 없앰. 코드 v4: 바뀐 부분만 다시 씀(해시), 단계별 저장, 오류에 단계 이름. 앱은 안드로이드에서 CapacitorHttp로 보내서 CORS 때문에 "Failed to fetch"만 보이던 문제를 없애고 구글 오류 내용을 보여 줌. 앱은 응답의 version 이 CODE_VERSION 보다 낮으면 "다시 붙여넣기" 안내.

- 그림 프롬프트: 1-1 복사로 1-1~1-3을 한 장에 그려 준 문제. 첫 컷 안내가 "아래 컷들을 순서대로"라서 여러 컷으로 읽힘 → "한 번에 하나씩 따로 요청" 문구로 바꾸고, 컷마다 "이 컷 하나만, 칸 나누기 금지" 규칙 줄을 붙임. 씬 전체 복사는 "첫 컷만 그리고 '다음'이라고 하면 다음 컷". 사람 없는 컷엔 차렷 문구 빼고, 샷은 한글 이름까지 표시.
- 구글 업로드 v4(오류 표시)는 사용자가 아직 시험 안 함. 사용자가 "급하지 않으니 다음에"라고 함.

- AI로 컷 나누기: 앱의 문장 단위 자동 분할보다 외부 AI(영화감독 역할)가 화면 단위로 더 잘 나눔(부당거래 S#1: 앱 4컷, GPT 7컷). 신 리스트 위 "AI로 전체 컷 나누기"(메시지가 너무 길다는 오류 때문에 시나리오는 .txt 파일로 저장·공유해서 첨부하고, 감독 역할 요청 문장만 복사. 씬 8개씩 답 받고 "다음") 와 씬마다 "AI로 컷 나누기". 답은 [n-k] 형식이나 표 형식 모두 읽음(prompts.ts parseCutSplitAnswer). 저작권 때문에 AI가 원문을 옮기지 않도록 대본 문장에 (1),(2) 번호(sceneUnits 순서)를 붙여 보내고, AI는 '대본 번호'/'대사 번호'만 답함 → 앱이 resolveNumbers 로 원문을 채움. 결과는 SceneMeta.aiCuts 에 저장, getCuts 가 우선 사용(키 `${sceneId}~ai${i}`), 화면 내용은 컷 desc(장면 묘사)로 들어감. AI 컷은 끌어서 합치기만 되고 ✂ 나누기는 없음. "자동으로 다시 나누기"로 되돌림.

- 외부 AI를 옆 화면(분할 화면)에: 공유하면 ChatGPT가 앱 화면을 덮던 문제. AppUpdaterPlugin 에 shareFile/openSide 추가 (FLAG_ACTIVITY_LAUNCH_ADJACENT | NEW_TASK | MULTIPLE_TASK). 파일 보내기·그림 보내기는 모두 이걸로. 상단 "AI 열기 ◫" 버튼, AI 컷 나누기 창에도 버튼. AndroidManifest 에 <queries> (ChatGPT, Gemini, Claude 패키지). 실제 갤럭시 탭에서 분할 화면으로 열리는지는 사용자 확인 필요.

- 붙여넣기 백슬래시: ChatGPT 답을 복사하면 `\[1-1\]`처럼 마크다운 이스케이프가 붙어 컷 번호를 못 읽던 문제. util.ts unescapeMd 로 붙여넣기(cleanPasted)와 parseCutSplitAnswer 에서 지움.
- AI 컷 나누기 묶음 크기: 8/15/30/전체 고르기(localStorage 'ai-split-per'). 묶음은 입력이 아니라 AI 답 길이 제한 때문. '전체'는 AI에게 컷나누기.txt 파일로 답하라고 요청하고, 창의 '답 파일 불러오기'로 읽음.
- 컷 나누기 + 장면 묘사 한 번에: 사용자가 컷 나누기 → 장면 묘사 씬마다 복사·붙여넣기가 번거롭다고 함. AI 컷 나누기 요청(DIRECTOR_RULES/ANSWER_FORMAT)에 씬마다 [설정표 n]과 자세한 '화면' 묘사 규칙을 넣음. parseSetTables 가 설정표를 읽어 applyAiCuts(…, setTable)로 씬 설정표에, 화면은 컷 desc로. 장면 묘사 탭의 씬별 복사는 다시 받을 때만 쓰면 됨. 답이 길어져서 묶음은 8씬 권장.
- 초벌 문제: GPT가 '자동 초벌이라 상세 최종본은 아니다'라고 답함. 요청에 '초벌 아님, 최종본, 질을 낮추지 말고 씬 수를 줄여 나눠 답' 규칙 추가. 묶음 기본 5씬(3/5/8/15/전체). 전체 모드는 여러 파일로 나눠 달라고 함. '"다음" 요청 복사' 버튼(buildNextRequest)으로 이어 받기.
- 8컷씩 감독 정밀 콘티: 사용자가 GPT와 대화해 보니 '감독 관점에서 컷마다 검토'를 시키면 자세해지고, 한 번에 8컷이 적당하다고 함. DIRECTOR_RULES 를 정밀 콘티(정보 공개 순서, 샷 연결, 위치·자세·시선·손동작·접촉, '연출:' 한 줄)로 바꾸고, 묶음 단위를 씬→컷(5/8/12, 기본 8, localStorage 'ai-split-cuts')으로. 씬 중간에서 끊긴 답([12-6]부터)은 앞 AI 컷을 살리고 이어 붙임(applyAiCuts keep). 연출 의도는 AICut.intent → Cut.auto.note 에 '연출:'로. '"다음" 요청 복사'는 마지막으로 넣은 컷 번호 다음부터 요청.
