AI가 옮겨 적기를 거절해도 번호로 동작.
- AI 전체 컷 나누기 씬 범위 (2026-11-03): 창에 'S#a ~ S#b' 고르기. 요청에 '이번엔 S#a~S#b만, 앞뒤는 흐름 이해용', '다음' 요청도 S#b까지만(buildNextRequest until).
- 웹툰 탭 (2026-11-03, WebtoonTab.tsx, webtoon.ts): 스토리보드와 분석 사이. 컷 그림을 너비 720px로 세로로 이어 보여 줌(씬 범위, 씬 제목). 그림 없는 컷은 회색 칸에 묘사.
  - 말풍선: 컷 대사로 자동. 위치는 장면 묘사에서 이름 뒤/앞의 '왼쪽·가운데·오른쪽'(charX), 없으면 등장 순서로 좌→우. 종류: 말/외침(!!, 소리친다)/생각/화면 밖 소리(off)/내레이션. 모양은 SVG, 꼬리는 CSS 삼각형(html2canvas가 SVG 바깥 꼬리를 못 그려서).
  - 효과음: AI가 준 '효과음:' 우선, 없으면 SFX_RULES(급정거→끼이익! 등). 글자 테두리는 text-shadow(저장 그림에도 나옴).
  - 화면효과: 집중선/속도선/번쩍/어둡게는 캔버스(drawFx, 컷 key 시드), 흔들림은 그림 겹치기. AI '화면효과:' 우선, 없으면 FX_RULES.
  - '말풍선·효과 고치기': 끌어서 옮기기, 눌러서 글/종류/말한 사람/꼬리 방향, 효과음 크기·기울기·색, 효과 켜고 끄기. 고치면 CutMeta.wt 에 저장, '자동으로 되돌리기'로 지움.
  - '그림으로 저장': 씬마다 JPG(html2canvas scale 1.5 → 너비 1080).
  - AI 컷 나누기 요청에 '효과음:', '화면효과:' 줄과 '말하는 인물의 화면 위치를 꼭 쓰기'를 추가. AICut.sfx/fx → Cut.auto.sfx/fx.
- 전체 설정 반영 + 다양한 앵글 (2026-11-03): 사용자가 '뒤 씬 설정이 반영 안 돼 엉뚱한 장면', '같은 방향에서 사이즈만 바뀜'이라고 함.
  - Project.bible(작품 설정): 전체 컷 나누기 첫 답 맨 앞 [작품 설정]을 parseBible 로 읽어 저장(없을 때만 자동, 있으면 '답의 작품 설정으로 바꾸기'). 컷 나누기 창에서 보기·고치기. 씬별 컷 나누기·장면 묘사 요청에 같이 보냄.
  - 씬별 컷 나누기도 '시나리오 파일 보내기' 버튼(권장) + [전체 씬 흐름](sceneOutline: 씬 제목, 첫 지문, 말하는 인물). 장면 묘사 요청도 작품 설정이 없으면 씬 흐름을 붙임.
  - DIRECTOR_RULES: 시나리오 끝까지 먼저 읽기, 카메라 위치·방향 다양화(OTS, POV, 리버스, 하이/로우/부감, 더치, 전경, 인서트, 리액션, 프레임 속 프레임), 커버리지·180도 선, 같은 위치 연속 금지, 렌즈·높이. 컷 머리줄: 샷 / 카메라 위치·방향 / 앵글 높이 / 움직임 / 렌즈 (cam 문자열이 그림 프롬프트 '카메라:'로 들어감).
- 3인 토론 (2026-11-03): 신 리스트 탭 '① 3인 토론' → '② AI로 전체 컷 나누기'. 외부 AI가 감독·작가·평론가로 시나리오를 5부(주제·구조 / 인물 / 톤앤무드 / 카메라 언어 / 씬별 연출)로 토론, 한 번에 1~2부씩 '다음'으로 이어 받음(buildDebateRequest, DEBATE_NEXT). 답을 '모으기'로 Project.debateLog 에 쌓고, [토론 결론]은 Project.debate(parseDebate), [작품 설정]은 bible 로 저장. 결론은 bibleBlock 으로 컷 나누기·씬별 컷 나누기·장면 묘사 요청에 모두 들어가고, 톤앤무드·색감 줄은 그림 프롬프트 공통부(autoCommon '작품 분위기')에 들어감.
- 바깥 정보 막기 (2026-11-03): 사용자가 '토론이 실제 영화 내용을 검색해 인용한다'고 함. 토론·컷 나누기 요청에 '웹 검색 금지, 실제 영화·원작·배우·리뷰·다른 작품 비교 금지, 첨부한 시나리오 글만 근거' 규칙. 세 사람은 가상 인물, 톤앤무드에서 '참고 영화' 뺌. 첨부 파일 이름은 '시나리오.txt', 파일과 요청에서 작품 제목을 뺌(제목으로 실제 영화를 떠올리지 않게).
- 토론 목적 바로잡기 (2026-11-03): 사용자 말 '시나리오를 고치거나 보완하는 토론이 아니라, 정해진 시나리오를 어떻게 이해하고 상상해서 인물·화면·표정·행동을 그려 낼지에 대한 토론'. buildDebateRequest 를 다시 씀: 확정본, 수정·보완·약점 지적 금지, 근거는 대본 글. 평론가 = 해석이 대본과 맞는지 따지고 놓친 단서를 찾는 첫 독자. 5부: 시나리오 읽기 / 인물 그려 내기 / 감정과 표정·행동 / 공간과 화면 / 씬별 화면과 카메라. 결론에 '공간', '씬별 화면' 항목.
- 토론 결론 자세히 (2026-11-03): 사용자 말 '긴 토론에 결론이 너무 심플'. DEBATE_FORMAT: 결론은 요약이 아니라 '연출 노트', 빠짐없이, 길어도 됨, 끊기면 [토론 결론 계속]. 머리표 [전체] / [인물 이름] / [공간 장소] / [씬 n](모든 씬). parseDebate 는 기록 전체에서 [토론 결론]이 다시 나오면 새로, [토론 결론 계속]은 이어 붙임. debateFor(p, scene)가 씬별 요청(씬 컷 나누기, 장면 묘사)에 [전체]+나오는 인물+이 씬 장소+[씬 n]만 넣음(머리표 없으면 전체). 토론 창 '결론 자세히 다시 받기'(buildDebateSummaryRequest), 1500자 미만이면 경고. 컷 나누기 창 '토론 기록 파일 보내기'(토론기록.txt). 결론이 있으면 화면 묘사 3~5문장, 눈·입·손·어깨까지 구체적으로.

## 윈도우용 (2026-11-02 추가)
사용자가 안드로이드 탭용과 윈도우용을 함께 개발하자고 함. 화면 코드는 하나(`tablet-app/src`), 윈도우는 Electron 껍데기(`tablet-app/desktop`)로 같은 빌드(dist)를 띄운다.
- 화면 주소는 `app://local/` (main.cjs 의 protocol.handle). 작품 저장(IndexedDB)이 이 주소에 묶이니 바꾸지 말 것.
- 파일 저장: 문서\시나리오작업실 에 저장하고 탐색기로 보여 줌(AI 창에 끌어다 놓기). 메뉴 '파일 → 저장 폴더 열기'.
- AI 열기 ◫: 앱을 화면 왼쪽 55%, ChatGPT 창을 오른쪽에 나란히 띄움. 로그인 유지(partition persist:ai), 구글 로그인 막힘을 피하려고 크롬 UA. AI 창에서 받은 그림은 문서\시나리오작업실\받은 그림 에 저장(앱에 'ai-downloaded' 알림은 보내지만 아직 자동으로 넣지는 않음).
- 화풍 그림 '외부 AI로 보내기': 클립보드에 그림 복사 → AI 창에서 Ctrl+V.
- 구글 자동 저장: main 프로세스 net.fetch 로 보냄(CORS 없음).
- 업데이트: 릴리스의 .exe 를 받아 실행하고 앱을 닫음(NSIS 한 번 클릭, 사용자 폴더에 설치, 관리자 권한 필요 없음). 버전은 VITE_BUILD(빌드 번호).
- Edge가 .exe 다운로드를 '일반적으로 다운로드되지 않음'으로 막고 '그래도 계속'이 안 보이는 경우가 있어서(사용자 겪음) 릴리스에 같은 설치 파일의 .zip 도 올림.
- 업데이트 400 오류 (2026-11-03): 사용자 PC에서 net.fetch 로 릴리스 .exe 를 받을 때 400. 여기(리눅스)에서는 재현 안 됨. Node fetch(UA 지정) → net.fetch(크롬 UA) 차례로 시도하고, 실패하면 다운로드 페이지를 엶. 사용자 PC에서 v1.0.28 이후 업데이트가 되는지 확인 필요.
- 코드 서명이 없어서 처음 설치할 때 "Windows의 PC 보호" 경고가 뜸 → "추가 정보 → 실행".
- 리눅스(xvfb)에서 실행 시험: 새 작품, PDF 불러오기(pdfjs 워커), 다시 켜도 작품 남음, AI 창 나란히 배치 확인. 실제 윈도우 PC에서는 사용자 확인 필요.
- 태블릿과 PC 사이 작품 옮기기는 아직 백업 파일(.sbk)로만 됨.
