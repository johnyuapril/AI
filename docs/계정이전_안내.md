## 1. 새 계정에서 시작하는 법

1. 새 Claude 계정에서 **GitHub 연결**: 같은 GitHub 사용자(johnyuapril)로 연결한다. 다른 GitHub 사용자라면 johnyuapril/AI 저장소의 Collaborator로 추가해야 push할 수 있다.
2. Claude Code(웹) 새 세션에서 저장소 **johnyuapril/AI** 를 고른다. (예전 이름 AI2 → AI로 바뀜. 지금은 이 저장소 하나만 쓴다. 공개 저장소.)
3. 첫 메시지로 아래를 붙여 넣는다.

```
이 저장소는 내 "시나리오 작업실" 앱이야 (갤럭시 탭 안드로이드 + 윈도우).
먼저 CLAUDE.md, docs/계정이전_안내.md, docs/HANDOFF.md 를 끝까지 읽고 지금 상태를 파악해.
규칙: 작업 하나 끝날 때마다 main에 커밋·push, push 때마다 docs/HANDOFF.md 갱신, 한국어 쉬운 말로 답하기.
다 읽었으면 "다음에 할 일"과 "확인 못 한 것"을 짧게 알려 줘.
```

4. 앱 빌드 비밀값(서명 키 비밀번호 `ANDROID_KEYSTORE_PASSWORD` 등)은 **GitHub 저장소 설정에 이미 들어 있어서** 새 계정에서 따로 할 일이 없다. `release.jks.enc` 파일은 절대 지우지 말 것 (지우면 태블릿 앱을 지우고 다시 깔아야 함).

## 2. 앱 한눈에 보기

- **무엇:** 시나리오를 불러와서 → 컷을 나누고 → 장면 묘사 → 그림 → 스토리보드(콘티) → 웹툰까지 만드는 앱.
- **어디서:** 갤럭시 탭(안드로이드 APK)과 윈도우(설치 파일 .exe/.zip). 화면 코드는 하나(`tablet-app/src`)를 같이 쓴다.
- **설치/업데이트:** main에 push하면 GitHub Actions가 빌드해서 https://github.com/johnyuapril/AI/releases 에 `Screenwriter-vN.apk`, `Screenwriter-Setup-1.0.N.exe`(+ .zip)을 올린다. 앱 홈의 "업데이트 확인"으로 받는다. **지금 최신: v1.0.55.** 파일 이름 규칙을 바꾸면 업데이트가 깨지니 바꾸지 말 것.
- **AI는 앱 안에서 부르지 않는다.** 모두 "요청 문장 복사 → 외부 AI(지금은 **Claude**)에 붙여넣기 → 답(또는 답 파일)을 앱에 넣기" 방식. 그림만 예외로, 사용자 PC의 ComfyUI를 앱이 직접 부른다.

## 3. 사용자가 원하는 방식 (꼭 지킬 것)

- **한국어, 쉬운 말.** 짧게, 결과부터.
- **최종본 품질.** "초벌"은 안 된다. AI가 뒤로 갈수록 줄여 쓰지 않게 해야 한다.
- **강제 규칙으로 채우지 말 것.** 예: "씬마다 무빙 하나 이상" 같은 개수 규칙은 사용자가 싫어함. 카메라 기법(어깨 너머/리버스, 인물 시점, 드론·지미집·크레인·달리·스테디캠·핸드헬드)은 **3인 토론에서 장면마다 자연스럽게 판단**하게 한다.
- **3인 토론의 목적:** 시나리오를 고치거나 보완하는 토론이 아니다. 확정된 시나리오를 어떻게 이해하고 인물·표정·행동·공간·화면으로 그려 낼지에 대한 토론. 세 사람(감독=연출, 작가=이야기·인물, 평론가=관객·해석)은 **서로 다른 전문가의 시선**으로 맞장구 없이 따진다. 바깥 정보(실제 영화, 검색, 리뷰) 금지.
- **토론 결과를 받는 사람은 "토론에 참여한 바로 그 감독"**이어야 한다. 토론 전체를 숙지하고 씬마다 그 씬의 논의를 확인하며 쓴다.
- **번거로운 반복 싫어함.** "다음"을 수십 번 치게 하지 말 것. 복사·붙여넣기 횟수를 줄이는 쪽으로.
- **저작권:** AI가 대본 원문을 옮겨 쓰는 요청은 거절당한다. 그래서 대본 문장마다 (1),(2) 번호를 붙인 파일을 주고 AI는 번호만 답한다 → 앱이 번호로 원문을 채운다. **원문을 옮겨 쓰게 하는 요청을 다시 넣지 말 것.**
- 쓰는 AI: **Claude** (앱의 기본값도 Claude).

## 4. 지금 쓰는 작업 흐름

1. **대본 탭:** 시나리오(HWP 등) 불러오기.
2. **신 리스트 → ① 3인 토론:**
   - "시나리오 파일 보내기"로 번호 붙은 `시나리오.txt`를 AI 대화에 첨부 (HWP를 그대로 첨부하면 번호가 안 맞음).
   - 토론 요청 복사 → Claude에 붙여넣기. "한 번에 끝까지(Claude 추천)"를 켜면 1~6부를 `토론.md` 파일에 스스로 이어 씀.
   - 6부 구성: 1 시나리오 읽기 / 2 인물 그려 내기 / 3 감정과 표정·행동 / 4 공간과 화면 / 5 씬별 핵심 순간과 분위기 / 6 씬별 컷과 앵글(가장 깊게). 끝나면 "토론 끝".
   - 토론 창에서 인물별 **캐릭터 시트 요청**(마커펜 러프 스토리보드풍)도 복사할 수 있다.
3. **② 토론 결과 받기:** 같은 대화창에 요청을 붙여 넣으면, Claude가 씬 3개씩 `콘티_S1-3.txt`, `콘티_S4-6.txt` … 파일을 **스스로 이어서** 만들고, 파일마다 "화면" 묘사 길이를 재서 줄었으면 다시 쓴다. 답 길이 한계로 멈추면 "계속"만 친다. 범위(S#a~S#b)를 골라 남은 씬부터 받을 수 있다.
4. 받은 파일 넣기: "답 파일 불러오기"(여러 개 한꺼번에) 또는 윈도우에서는 **"AI 창에서 받은 파일 넣기 (n개)"**. → 씬마다 설정표, 컷(카메라 줄: 크기 / 샷 종류 / 위치 / 앵글 / 장비·움직임 / 렌즈), 화면 묘사, 연출, 효과음, 화면효과가 들어간다.
5. **그림 탭:** ComfyUI로 컷/씬 그리기 (캐릭터 시트 그림을 참고 그림으로 넣을 수 있음). 또는 외부 AI용 프롬프트 복사.
6. 스토리보드 → 웹툰 → PDF/JPG 저장.

## 5. 최근 개발 내역 (v1.0.39 ~ v1.0.55, 2026-11-10 ~ 11)

- ChatGPT 붙여넣기의 `\` 기호 자동 제거.
- 컷 나누기와 장면 묘사를 한 번에 받기. 감독 역할 "정밀 콘티" 규칙.
- 3인 토론: 세 사람의 전문 시선 분리, **6부(씬별 컷과 앵글)** 추가, 한 번에 끝까지(파일) 모드, 결론을 앱에 다시 가져오지 않고 결과만 받기.
- 캐릭터 시트 요청문(토론 2부 결과를 따름, 마커펜 러프 스타일).
- **ComfyUI 연동:** 윈도우 앱을 켜면 ComfyUI 자동 실행·자동 설정. Qwen-Image 2.1 워크플로를 서버의 노드 목록을 보고 자동 구성, 없으면 SDXL. 캐릭터 시트를 참고 그림으로.
- 쓰는 AI 고르기(기본 Claude), 윈도우 AI 옆 창.
- AI 답 읽기: "S#19 … C1 WS, …" 같은 목록도 읽음. 대본 번호가 앱 파일과 안 맞으면 자동으로 **내용으로 맞추기**(또는 "대본 번호 무시" 체크).
- 원문 옮겨 쓰기 요청 삭제 (저작권 거절 방지) — v48.
- 카메라 다양성: 강제 규칙 없이 토론 6부에서 판단 (v51). 카메라 줄에 OTS·POV가 있으면 샷으로 표시.
- **147씬을 한 파일로 받았더니 뒤로 갈수록 대본 수준으로 줄어든 문제** → 씬 3개씩 파일로 나눠 스스로 이어 쓰기 + 길이 자가 점검 + "화면 3~5문장" (v52~53).
- 토론 결과는 "토론에 참여한 바로 그 감독"이 토론 전체를 숙지하고 씀 (v54).
- 한글 파일에서 "이름[탭]대사" 다음 줄 지문이 대사로 붙던 문제 → 지문으로 읽기 (`script.ts` looksNarration). 이미 넣은 컷은 답 파일을 다시 넣어야 반영.
- **윈도우 AI 옆 창에서 파일 받기가 반응 없던 문제** → 창 안에서 받고(`문서\시나리오작업실\받은 파일`), 알림, 바로 넣기 버튼 (v55).

그 이전(v1~v38)의 내역은 `docs/HANDOFF.md`에 날짜별로 있다 (웹툰 탭, 구글 자동 저장, 작품 설정, 토론 결론 연출 노트, 윈도우 앱 등).

## 9. 함께 쓰던 파일 (프로젝트 공유 폴더)

이 계정의 프로젝트 공유 폴더에 있던 것 중 다시 필요한 것:
- `guides/ComfyUI_설치와_연결.md` — 저장소 `docs/COMFYUI.md`와 같은 내용.
- `prompts/캐릭터시트_요청문.txt` — 앱의 캐릭터 시트 요청과 같은 내용.
- `storyboard-style.md`, `specs/` — 예전 스토리보드 스타일·사양 메모.
- 화면 캡처(.png) 다수 — 개발 중 확인용.

필요하면 이 계정에서 내려받아 새 계정 대화에 첨부하면 된다. 앱 코드와 문서는 전부 GitHub 저장소에 있어서 따로 옮길 필요 없다.

**작품 데이터(시나리오, 컷, 그림)는 앱 안(기기)에 저장돼 있다.** 계정을 바꿔도 앱 데이터는 그대로다. 기기를 바꿀 때는 앱의 백업(.sbk / 전체 백업 zip)을 쓴다.
